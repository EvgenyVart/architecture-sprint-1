Описание проекта:

Проведен предварительный анализ проекта;

Для разделения проекта выбрал смешанный подход в определении границ:
**По функциональной декомпозиции** выделил "Загрузку фотографии" в отдельный микрофронтенд,
т.к. функция загрузки файлов в принципе очень дорогая функция, и не имея более детального
описания по объемам загружаемых файлов. Нам это позволит организовать отдельную функцию
добавления фотографии и при необходимости горизонтально масштабироваться при нагрузке, отдельно 
от остальных сервисов.
**По DDD** выделил домены как пользователь (профиль) и фотографии, их так же вынес в отдельные микросервисы.

Метод реализации и сборки выбрал серверная компоновка, т.к. достаточно статичный интерфейс, и скорость
при работе с фотографиями думаю необходима;

Фреймворк для организации  Webpack Module Federation, т.к. на лабораторной работе получил небольшой 
опыт взаимодействия именно с этой технологией и ни каких ограничений с ее использование в данном проекте не встретил.

При анализе проекта выделил общий компонент взаимодействия через CurrentUserContext,
в связи с этим profile-microfrontend выбран как host проект. Вариант межмодульного взаимодействия 
предположительно Pub/Sub (как пример для информирования компонента списка фотографии, 
со стороны компонента загрузки фотографии, авторизация и логаут пользователя)

Стили CSS оставлены в проекте с profile-microfrontend, т.к. это главный проект,  при инициализации подпроектов
стили из host-проекта будут применяться к их компонентам.

Для запуска приложения все микросервисы должны быть запущены;
